# Tutorial assets

Sources, licences and hashes of everything the lobby tutorial bundles. The loader is `Samples/Scripts/Tutorial/TutorialAssets.cs`;
the files live under `Resources/TutorialAssets/` (so they are force-tracked, `**/Resources/` is gitignored).

## Narration (no audio is bundled)

The tour's lines and the arrival notices are shown as **subtitles**. No narration audio ships with this repository: the clips the
project recorded were generated on a free ElevenLabs plan, which does not allow redistribution under this repository's licence.
Without a clip, `TutorialController.PlayVoice` returns the line's reading time (`TutorialNarrator.ReadingSeconds`: 2.5 words a
second, 2 to 12 s), so the subtitle, the pacing and a step that completes when its line is heard behave as with a voice, and the
voice credit (`TutorialScript.AttributionLine`) is not shown (`TutorialAssets.HasNarration`).

To add a voice, record each line below and put it at `Resources/TutorialAssets/Audio/<clip>.mp3` (the tour) or
`Resources/TutorialAssets/Arrival/<clip>.mp3` (the arrival notices); make sure your licence for the audio allows the use you make
of it, and add its source and licence here.

## Sample scan assets (synthetic, CC0 1.0)

The photo, the vase and the lamp are our own work, generated by `tools/make_tutorial_assets.py` from a hand-written profile, with no third-party model, photo
or texture and none of anyone's captures. The script is deterministic: running it again reproduces these hashes. They are stored as
`.bytes` text assets so they stay readable at run time (`sample_photo` is decoded with `Texture2D.LoadImage`, `sample_object` is a
binary glTF) and the model is not imported as a prefab.

How the canned scan uses the mask (`CannedScanTransport` / `CannedSegmenter`): a Segment request whose click points include one on the vase (mask value non-zero at that pixel) is answered with this mask; points all off the vase select no object and the canned server reports the Segment as failed (the panel then shows no overlay and holds no mask, so Reconstruct 3D asks for a tap on the object first). The real server answers a click on the floor or wall with that surface's mask (observed 2026-10-23: floor 12,402 px, wall 149,253 px); the tutorial does not ship those, its sample photo has one object to select. The mask goes through the same path as a real answer: the scan service reads it from the file the transport wrote, and the scan panel draws it with its own mask overlay.

With the capture card (scan UI Concept A) the tutorial does not show the sample photo: a practice vase
(`sample_object`) stands in the user's drawn box, the "photo" is a render of it from the user's eye
(`TutorialHologramFrameSource`), and the canned server answers the card's box prompt with that render's silhouette (the
projected outline of the vase without a graphics device). `sample_photo` and `sample_mask` stay as the canned server's
default and as test fixtures (a box holding at least half of the vase, or a click on it, selects it).

To regenerate the mask: call a scan server's `/spatialblend.scan.v1.ReconstructionService/Segment` with the photo and the two points above, and keep the returned bytes. Whether the mask stays byte-identical depends on the model version.

To check: `python3 tools/make_tutorial_assets.py /tmp/out && shasum -a 256 /tmp/out/*`; the two generated hashes match the table
(the `.bytes` files are those files renamed).
