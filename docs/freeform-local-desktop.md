# Freeform local desktop

`FreeformLocalApp` is a small, in-process desktop demonstration. It uses the
`SpatialBlend.Freeform` content catalog and ordinary Unity views, plus one
app-owned Foundation `SpatialBlendLocalWorld` with explicitly registered source and
receiver view objects in separate local spaces. It does not require Photon,
Meta, or an input SDK; it does not load or modify the legacy Freeform scene,
adopt a world, or join a scene-owned world.

## Run it

1. Open any scene and create an empty GameObject.
2. Add `FreeformLocalApp` from `SpatialBlend.Freeform`.
3. Enter Play Mode. The component creates an app-owned workspace containing
   source and receiver placements for one whiteboard and one chess board.

If no Camera is assigned, the component creates an app-owned desktop camera.
Assigning a Camera uses it for ray projection only: its transform, settings, and
lifetime are not changed. Disable **Create Camera When Unassigned** to require
an explicitly assigned camera; initialization then reports an actionable error
instead of mutating the scene.

The component includes a compact OnGUI desktop surface for local commands. Its
interaction is: drag over the receiver whiteboard; select a receiver chess piece
and then select a board square; clear/remove/recreate content from the panel.
The OnGUI path delegates to `TryHandleDesktopPointer` with the event's converted
bottom-left screen coordinate, phase, and UI-interception result. The handler
uses the assigned camera and receiver colliders, owns a whiteboard
press/drag/release sequence, and ignores/cancels content input intercepted by
the UI.

## Script commands

The component is deterministic and can be driven without desktop input:

```csharp
if (app.Initialize(out string error))
{
    app.DrawWhiteboardUv(new Vector2(.2f, .2f), new Vector2(.8f, .8f), Color.blue, 2, out error);
    app.TryMoveChessPiece("white-pawn-a2", new Vector3(.1f, .16f, 0f), Quaternion.identity, out error);
    app.ClearWhiteboard(out error);
    app.RemoveContent(FreeformLocalApp.DefaultWhiteboardContentId);
    app.CreateDefaultContent(out error);
}
```

`DrawWhiteboardWorld` uses the receiver view's actual local projection.

The original Freeform receiver now declares its whiteboard as a versioned local
XY surface chart (the legacy centred unit quad remains the default profile).
Its native Affordance support is a renderer-plane child with collider-native
geometry disabled; authored rendering, physics, and pointer input stay
separate. This is receiver support only: the scene does not invent a source
board, self-map it, or establish a board/chair correspondence. A future
cross-space integration must supply distinct live source and receiver
counterparts and own/dispose that correspondence lease explicitly.
`TrySelectChessPiece` and `TryMoveSelectedChessPiece` provide deterministic
selection/move commands; the latter delegates to `TryMoveChessPiece`.
`TryHandleDesktopPointer(Vector2, FreeformDesktopPointerPhase, bool, out error)`
is the deterministic screen-input entrypoint. Its `Vector2` is Unity screen
space (bottom-left origin, matching `Camera.WorldToScreenPoint`); a `true`
return means local content consumed the pointer, while UI-intercepted input is
intentionally ignored. PlayMode coverage exercises its camera-ray/collider path
for whiteboard model/view updates and chess selection/movement; graphical
acceptance is supplied only by the explicit gate below.
`Teardown` removes the two local models, unbinds views, unregisters/shuts down
its owned local world, and destroys only workspace objects, generated materials,
model hosts, and a camera generated by this component.

## Verification modes

The normal Foundation gate remains headless and excludes the
`FoundationGraphics` fixture:

```bash
bash tools/run-foundation-tests.sh --native-library /absolute/path/libspatialblend.dylib
```

Use the explicit graphical gate on a machine with a non-null Unity graphics
device:

```bash
bash tools/run-foundation-tests.sh --native-library /absolute/path/libspatialblend.dylib --graphics
```

The graphical fixture enters Play Mode, sends a whiteboard stroke through the
screen-coordinate pointer entrypoint, renders the app-owned camera into an
offscreen `RenderTexture`, and checks the projected stroke, board tile, and
piece regions after `ReadPixels`. It writes
`freeform-local-graphics-overview.png` into the temporary Foundation
verification-project root (`SPATIALBLEND_FOUNDATION_ARTIFACTS_DIR`, set by the
runner; run elsewhere it goes to `Application.temporaryCachePath`, never into
the repository) for visual inspection, then restores the camera's
render target and destroys its capture textures. This describes the gate's
acceptance contract; it does not claim a successful renderer run until that
graphical command has produced a passing result.


## Limits

This is a local visual/content surface, not a replacement for the legacy
collaboration app. It has no Photon, Meta SDK, Input System dependency,
session/room state, authority, replication, reconnect, voice, persistence,
chess rule engine, or multi-user input. It displays the standard 8x8 starting
layout with 32 stable, typed piece IDs, but permits free placement: it does not
validate turns, legal moves, captures, check, or mate. Existing scene objects,
cameras, and worlds are deliberately not adopted or changed.
